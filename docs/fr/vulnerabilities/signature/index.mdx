Les analyses de ce groupe détectent les défauts de validation de signature.

- [Algorithme JWT None](./jwt-alg-none) — L'acceptation de l'algorithme « none » dans un JSON Web Token (JWT) survient lorsqu'un JWT est signé avec l'algorithme « none » ; cela signifie qu'il n'y a pas de signature, ce qui facilite la falsification du contenu du token par un attaquant sans être détecté.
- [Signature JWT nulle](./jwt-null-signature) — La vulnérabilité de signature JWT nulle survient lorsqu'un JSON Web Token (JWT) n'a pas de partie signature, permettant aux attaquants de manipuler le contenu du token.
- [Signature psychique JWT](./jwt-psychic-signature) — La vulnérabilité « Psychic Signature » (CVE-2022-21449) affecte les implémentations de vérification ECDSA qui échouent à rejeter une signature à zéro (r=0, s=0), permettant aux attaquants de forger des tokens pour n'importe quel message et n'importe quelle clé publique.
- [Signature JWT non vérifiée](./jwt-signature-not-verified) — Une vulnérabilité où le serveur accepte des JWT sans vérifier leur signature cryptographique, permettant aux attaquants de forger des tokens arbitraires.
- [Confusion d’algorithme JWT](./jwt-algorithm-confusion) — La confusion HMAC (aussi appelée confusion d'algorithme) est une vulnérabilité JWT critique où un attaquant piège un serveur pour qu'il vérifie un token asymétrique (comme RS256) avec un algorithme symétrique (comme HS256).
